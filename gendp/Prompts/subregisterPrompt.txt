# Overview
I would like to add a new feature to gendp called subregisters. Essentially, for the gr register in
pe and pe_array I want to be able to access the left and right halves of gr[X]. For example, if we
had gr[15], this is a 32 bit register. I want to be able to access gr[15] >> 16 as gr[47], and I
want to access gr[15] && 0xFFFF as gr[31]. More generally, gr[x] is 32 bits, gr[x+16] is the lower
16 bits and gr[x+32] is the higher 16 bits. This is particularly useful for GWFA where we pack node
id and offset into a single 32 bit value because it allows us to save time bit shifting to get the
correct value.
# Details
+ You'll need to add 2 more bits for reg_0 and reg_1 in the scripts_utils.py as well as all over for
   instruction parsing
+ I recommend a new accessor, gr.at(X) which will return the register[X] if it is less than 16, but
   if more, then it will return the appropriate half register. For now, gr[48:63] are reserved for
   future use. It should throw an error if they are accessed.
+ Because for the most part the code (and the alu) operate on signed int32, the at operator should
   always return signed int32. After extracting a 16 bit value, it will pad the rest with the most
   significant bit (in c++ we just cast to int32)
+ Likewise we will need an accessor for writing to gr, gr.st(idx, val). if idx indexes a 16 bit
   field, then we will need to cast the 32 bit register to 16 bit. If the value does not fit in 16
   bit representation an exception should be raised and the program will terminate.
+ You should update all the code in the simulator to use these accessors instead of direct brackets.
